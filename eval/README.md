# Evaluation

`testset.json` is a hand-written bilingual (English/Arabic) question and
reference-answer set, grounded in the notes under `data/raw/`. Each item
records the source note file so results can be traced back to the
underlying clinical text.

`results.csv` is generated by running `python -m src.eval.run_eval` (see
`src/eval/run_eval.py` and `src/eval/ragas_harness.py`); it is not hand
edited.

## Running the evaluation

```
python -m src.eval.run_eval
```

Requires `GROQ_API_KEY` in `.env` (same key the agent's `generate` node
uses) - the RAGAS judge reuses the agent's own Groq chat model, and the
same multilingual sentence-transformers model already used for dense
retrieval, so the evaluator doesn't need a separate LLM provider or API
key.

## Environment notes (Windows + Python 3.14)

At the time this was built, installing `ragas` cleanly on Windows with
Python 3.14 hit two unrelated snags worth knowing about if you're setting
up a fresh environment:

1. `ragas`'s newest release (`>=0.4`) depends on `scikit-network`, which
   has no prebuilt wheel for `cp314` on Windows and fails to build without
   Microsoft C++ Build Tools installed. `scikit-network` is only used by
   RAGAS's knowledge-graph-based *testset generation* feature, which this
   project doesn't use (the test set here is hand-written), so it's safe
   to install `ragas` with `pip install --no-deps ragas==0.4.3` and then
   install its other runtime dependencies individually (see the
   dependency list in `ragas`'s own metadata) instead of pulling in
   `scikit-network`.
2. Because of (1), `ragas` was installed without letting pip resolve the
   already-installed (newer) `langchain-community` version against it.
   `ragas==0.4.3`'s LLM wrapper module does `from
   langchain_community.chat_models.vertexai import ChatVertexAI` at import
   time, but that submodule was removed from recent `langchain-community`
   releases (Vertex AI support moved to a standalone package). Since this
   project never uses Vertex AI, a tiny compatibility shim module was
   added at `langchain_community/chat_models/vertexai.py` in the
   environment's site-packages, exposing a `ChatVertexAI` placeholder that
   raises `ImportError` only if actually instantiated. This is an
   environment-level workaround, not project code - if you hit the same
   `ModuleNotFoundError` on a fresh install, either add the same shim or
   install `langchain-google-vertexai` (unused, but satisfies the import).

If a future `ragas` release fixes either of these, this workaround can be
dropped and `pip install ragas` used normally.
